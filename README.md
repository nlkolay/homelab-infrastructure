# High-Availability Homelab & Media Cluster: Infrastructure as Code

Декларативное описание отказоустойчивой гибридной инфраструктуры микро-ЦОД на базе гипервизора Proxmox Virtual Environment и аппаратной платформы AMD Ryzen Embedded R1505G.

Проект реализует практики надежности SRE (целевой уровень доступности сервисов — 99.9%), многоуровневое хранение данных (Storage Tiering), изоляцию сетевых сегментов и глубокий тюнинг сетевого стека Linux.

## 📦 Стек микросервисов (LXC 102 Container)

Все службы развернуты внутри контейнера Debian 12 с параметром `network_mode: host` для исключения накладных расходов виртуализации сети и прямого доступа к аппаратным интерфейсам:

### 1. Представление и мультимедиа
* **Homarr (порт 7575):** Центральная панель управления v1.0+, дашборд реального времени с интеграцией виджетов *Arr, qBittorrent и мониторинга инфраструктуры.
* **Lampac (порт 9118):** Локальный прокси-сервер метаданных и агрегатор плагинов каталога, работающий в контейнере на базе официального рантайма Microsoft .NET 9.0.
* **Jellyfin (порт 8096):** Потоковый медиасервер с поддержкой аппаратного ускорения транскодирования AMD VAAPI через прямое пробрасывание символьных устройств `/dev/dri/renderD128` и `/dev/dri/card0`.
* **Overseerr (порт 5055):** Сервис управления заявками пользователей и каталогизации с автоматической передачей задач на загрузку в Radarr и Sonarr.
* **TorrServer (порт 8090):** Демон потокового воспроизведения торрент-контента на лету с записью буфера на диск.

### 2. Автоматизация конвейера загрузок (*Arr Stack)
* **qBittorrent (порт 8080):** Клиент P2P-сетей с выделенным дисковым кэшем в оперативной памяти (2048 МБ) для агрегации мелких операций записи и снижения износа жестких дисков.
* **Prowlarr (порт 9696):** Единый менеджер поисковых индексаторов и трекеров с автоматической синхронизацией категорий контента.
* **FlareSolverr (порт 8191):** Прокси-сервис обхода антибот-защиты и вызовов проверки Cloudflare Challenge.
* **Radarr (порт 7878):** Менеджер фильмов с интеграцией мониторинга и сортировки релизов.
* **Sonarr (порт 8989):** Менеджер сериалов и аниме с поддержкой многосезонных очередей.
* **Bazarr (порт 6767):** Автоматизированный сервис загрузки текстовых внешних субтитров формата SubRip (SRT) для исключения перекодирования на клиентских телевизорах.

### 3. Мониторинг, СХД и системный доступ
* **Uptime Kuma (порт 3001):** Локальный мониторинг контрольных точек инфраструктуры (DNS, HTTP-эндпоинты, открытые порты) с Telegram-алертингом.
* **Jellystat (порт 3000) + PostgreSQL:** Аналитическая платформа для отслеживания сессий воспроизведения и сбора пользовательской статистики.
* **FileBrowser (порт 8081):** Веб-проводник для управления локальными накопителями без необходимости подключения по SSH.
* **Caddy:** Реверс-прокси с автоматическим получением сертификатов Let's Encrypt для шифрования внешнего доступа к умному дому.

## 💾 Архитектура подсистемы хранения (Storage Tiering)

Для балансировки нагрузок и сохранения ресурса накопителей реализована раздельная модель хранения:

1. **Горячий уровень (Hot Tier / NVMe):**
   * Размещен на системном SSD объемом 512 ГБ.
   * Хранит корневые файловые системы виртуальных машин, базы данных SQLite и PostgreSQL, кэш метаданных и конфигурации сервисов.
2. **Холодный уровень (Cold Tier / MergerFS Pool 2.3 ТБ):**
   * Объединяет физические диски `sdc` (1.8 ТБ) и `sda` (250 ГБ) с файловой системой ext4 в единую точку `/mnt/media_pool`.
   * Используется политика размещения файлов `mfs` (Most Free Space) с отсечкой `minfreespace=50G` — новые файлы автоматически записываются на диск с наибольшим остатком емкости.
   * Выделен исключительно под готовую структурированную медиатеку (чтение без интенсивной перезаписи).
3. **Выделенный кэш транскодирования (Jellyfin Transcode Cache):**
   * Физический накопитель `sdb` (250 ГБ) полностью выведен из общего пула и смонтирован по пути `/jf_cache`.
   * Принимает на себя циклическую запись сотен временных фрагментов видеопотока `.ts`, исключая деградацию пропускной способности основного пула при просмотре тяжелых релизов.
4. **Уровень временных загрузок (Scratch Tier / sdi):**
   * Физический накопитель `sdi` (465 ГБ) выделен под рабочую папку qBittorrent (`/data/torrents`).
   * Принимает фрагментированный ввод-вывод P2P-сети. После завершения скачивания файл перемещается в основной архив на `MergerFS`.

### 1. Архитектура сбора метрик (Метрический стек)
* **Prometheus:** Конфигурация с циклом опроса пятнадцать секунд и хранением базы временных рядов (TSDB) в течение тридцати суток.
* **Аппаратный мониторинг:** `smartctl-exporter` опрашивает контроллеры физических накопителей раз в минуту, предоставляя данные по температуре, переназначенным секторам и ошибкам передачи данных без необходимости выполнения периодических тяжелых фоновых скриптов.
* **Контейнерная телеметрия:** `cAdvisor` отслеживает утилизацию ресурсов каждым отдельным контейнером (лимиты памяти, троттлинг процессора, объем сетевого ввода-вывода).
* **Системный уровень:** `node-exporter` собирает метрики очередей ядра, сетевых интерфейсов, дисковой активности (`iowait`) и состояний энергосбережения ядер процессора (`cpu c-states`).

### 2. Централизованный сбор логов (Logging Pipeline)
* **Агент доставки логов (Fluent Bit):** Выбран вместо ресурсоемких Logstash и Filebeat. Написанный на языке Си, агент обрабатывает тысячи событий в секунду, потребляя менее тридцати мегабайт оперативной памяти. Агрегирует системные журналы с хоста, журналы Docker-демона и принимает сетевой `syslog` от пограничного маршрутизатора OpenWrt.
* **Хранилище и индексация (OpenSearch):** Развернута специализированная легковесная конфигурация для одиночной ноды (`single-node`). Размер кучи Java Virtual Machine жестко ограничен полутора гигабайтами (`-Xms1536m -Xmx1536m`), что предотвращает конкуренцию за память с мультимедийными сервисами. Базовые индексы хранятся на горячем пуле NVMe.
* **Интеграция с мониторингом доступности:** Оповещения и события недоступности сервисов из `Uptime Kuma` отправляются по протоколу HTTP Webhook напрямую во `Fluent Bit` и индексируются в общем журнале событий безопасности.

### 3. Инженерные команды управления мониторингом

## 🛡️ Сеть, Безопасность и Аппаратный Тюнинг

### Оптимизация сетевых контроллеров Realtek RTL8111H
Для предотвращения деградации гигабитного линка в 100 Мбит/с под управлением драйвера ядра `r8169`:
* Внедрен systemd-юнит `nic-optimize.service`.
* На физическом уровне принудительно отключено энергосбережение IEEE 802.3az (Energy Efficient Ethernet).
* Деактивированы прерывания Wake-on-LAN для исключения коллизий на шине PCIe.
* Зафиксирован дуплексный гигабитный режим автосогласования.

### Защита периметра и изоляция
* **Защита DNS:** Входящие пакеты на порт 53 из зоны WAN безусловно сбрасываются правилами межсетевого экрана `nftables` (защита от атак DNS Amplification).
* **Гостевая изоляция:** Гостевые VPN-узлы изолированы на уровне межсетевого экрана гипервизора Proxmox политикой `DROP`, исключая возможность доступа к управляющей подсети и внутренним устройствам LAN.
* **Торрент-трафик в обход прокси:** Для узлов с интенсивным трафиком настроены правила возврата пакетов `counter return` в цепочке `mangle_prerouting`, предотвращающие захват P2P-пакетов модулями прозрачного проксирования и переполнение оперативной памяти маршрутизатора.

## 🔧 Пошаговое развертывание

### 1. Настройка физического хоста (Proxmox VE)

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/nlkolay/homelab-infrastructure.git /opt/homelab-infrastructure
   cd /opt/homelab-infrastructure
   ```
2. Настройте монтирование дисков и пула MergerFS:
   ```bash
   cp storage/fstab.example /etc/fstab.homelab
   # Перенесите строки накопителей в рабочий /etc/fstab
   bash storage/setup-storage.sh
   ```
3. Установите службу сетевой оптимизации:
   ```bash
   cp systemd/nic-optimize.sh /usr/local/bin/
   chmod +x /usr/local/bin/nic-optimize.sh
   cp systemd/nic-optimize.service /etc/systemd/system/
   systemctl daemon-reload
   systemctl enable --now nic-optimize.service
   ```
4. Настройте конфигурацию файлового доступа:
   ```bash
   cp samba/smb.conf /etc/samba/smb.conf
   systemctl restart smbd
   ```

### 2. Запуск контейнерного стека (LXC 102)

1. Убедитесь в наличии проброса устройств в конфигурации контейнера `/etc/pve/lxc/102.conf`:
   ```text
   mp0: /mnt/media_pool,mp=/data/media
   mp1: /mnt/disk_trash,mp=/data/torrents
   mp2: /mnt/disk_aux2/jf_cache,mp=/jf_cache
   lxc.cgroup2.devices.allow: a
   lxc.mount.entry: /dev/dri/renderD128 dev/dri/renderD128 none bind,optional,create=file
   lxc.mount.entry: /dev/dri/card0 dev/dri/card0 none bind,optional,create=file
   ```
2. Внутри контейнера скопируйте файл переменных и запустите Compose:
   ```bash
   cd /opt/media-server
   cp .env.example .env
   # Отредактируйте пароли и секреты в .env при необходимости
   docker compose up -d
   ```
3. Проверьте запуск всех служб:
   ```bash
   docker compose ps
   ```
